## Notes (design risks / follow-ups — non-gating)
- **N1 — The two strongest proofs skip in a bare CI env.** The real-docling PPTX test is `importorskip("docling")`-gated and the two live-DB proofs (persist→reuse, RAG grounding) skip when Postgres is unreachable. In the curated CI venv the exit criterion therefore rests on faked-edge tests + the offline RAG seam; the authoritative live proofs were actually run green locally against compose Postgres (documented). This is the accepted P2-09/P4-10 posture and honestly disclosed, so it does not gate. Standing follow-up (not P5-scoped): wire a phase-exit CI job around `make test-integration-full` so the live proofs gate somewhere, rather than only on a developer's machine.
- **N2 — VLM-OCR path not exercised.** plan.md P5 says "*reserve* a VLM-OCR path for hard docs"; `app/ingestion/vlm.py` exists as that reserved seam. The exit criterion (scanned PDF + PPTX) does not require it, so its absence from this verification is correct scoping, not a gap.
- **N3 — "Usable profile" (point 4) is a structural guard, not an LLM-quality proof.** The non-empty profile is injected by the faked completer, so the assertion proves the pipeline preserves/validates a real profile and that an empty one would fail — it does not prove the live LLM extracts good fields (correct: the LLM is a true external edge; P5-03 unit-tests the structurer). Acceptable posture.
- **N4 — Real Celery→Redis `update_state` wiring not exercised end-to-end.** Async is proven via a fake enqueuer + scripted `AsyncResult`; the producer/consumer contract is bound only through the shared `STATE_PARSING/STRUCTURING/PERSISTING` constants and terminal result shape. This is the accepted P4-10 fake-broker posture; drift would fail the lifecycle test. Non-gating.
- **N5 — "No gap in P5-01..P5-07" is well-supported.** All referenced classes/functions were verified to exist and are driven as the *real* implementations (not re-stubbed), each of the 7 exit points maps to a concrete assertion, and all prior P5 tasks are `DONE` with dual approvals. The phase conforms to plan.md + design §5.1/§5.3/§4 as a completed phase.

The P5 exit criterion is genuinely proven end-to-end (scanned PDF OCR fallback + PPTX docling primary → async with progress → usable structured profile → persisted/reusable → RAG-grounded through one shared pgvector store), and the whole P5 phase conforms as completed.
