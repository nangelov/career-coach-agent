| C1 | minor | app/agents/web_searcher.py:270 | The crawler `GET`s arbitrary URLs returned by SearXNG with `follow_redirects=True` and no host/IP allowlist. A search result (or a redirect off a public page) pointing at `127.0.0.1`, a private/link-local range, or the cloud metadata endpoint (`169.254.169.254`) would be fetched server-side — an SSRF vector, more pointed here because v2 co-locates Redis/Postgres on the same host/network. Likelihood is bounded (attacker must influence a search result) and the extracted text is inert, so not gating — but this is a genuinely new server-side fetcher of untrusted URLs. | Track for P10 (untrusted-content hardening): reject non-`http(s)` schemes and resolve-then-block private/loopback/link-local/metadata IP ranges before fetching, and reconsider unbounded redirect following (cap hops or re-validate each redirect target). At minimum leave a `# TODO(P10): SSRF allowlist` marker so it is not lost. |
| C2 | nit | app/agents/web_searcher.py:251 | Crawl is sequential, so worst-case worker latency is `max_crawl × crawl_timeout` (3 × 8s = 24s), and because all workers fan in to the responder this stalls the whole turn on the slowest path. Correct and bounded, just potentially slow. | Optional: bound with `asyncio.gather` over the (already capped) target set, or a shorter per-page timeout. Fine to defer. |

## Notes

No real network in any test.
- Tool-arg / payload parsing is fully guarded (matches the recurring project check): `_parse_results` guards `isinstance(payload, dict)` and `isinstance(raw, list)` and coerces every field with `str(...)` before use, and skips non-dict items — a malformed/`null`/wrong-type `results` payload degrades to `[]` rather than raising out of the fail-soft node. `_error_message` is equally defensive.
- `except Exception` in `_crawl_page` / `_extract_text` is intentional per-URL fail-soft and does not swallow `CancelledError` (that is `BaseException` on 3.11), so client-disconnect cancellation still propagates. Both log at `warning` so real outages stay observable.

The two `test_agent_graph.py` fan-in tests were correctly re-pointed from the removed stub's canned marker to the real worker's output — a legitimate adaptation, not a weakened assertion.
- In-lane note (design conformance is the system-architect's call): the `content` bundle passes crawled text to the responder without an explicit untrusted-source delimiter; the task correctly assigns that delineation to the responder (P4-06) and the injection classifier to P10, so it is not a defect here.
