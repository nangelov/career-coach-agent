The real router `stream` and the fake are both async generators (so `aclose` exists and is invoked); double-close after normal exhaustion is a safe no-op. Mid-stream router failover is handled inside `LLMRouter.stream` (resume semantics); the responder only sees a terminal `LLMAllModelsFailedError` after all models are exhausted and degrades to a terminal `finish_reason="error"` chunk (content suppressed when tokens already flowed) — correct.

Documented as the chat-endpoint task's concern (guardrails/memory on the streamed answer, compiled-graph reuse). Given P10 guardrails are still stubs, no gate.
