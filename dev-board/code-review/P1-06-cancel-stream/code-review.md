## Notes
- **Verification reproduced locally** (from `backend/`): `ruff check .` → all passed; `mypy app/` → success, 31 files; `pytest -q` → **62 passed**. Matches `engineer.md`.
- **Acceptance criteria all met:** cancel endpoint sets a Redis-backed flag and returns promptly (202, delegates, opens no stream — `test_cancel_endpoint_returns_promptly_and_delegates`); in-flight stream observes the flag and stops within a bounded chunk count, emitting the terminal `cancelled` event; sessions are isolated (keyed `session:cancel:<id>`, `test_cancel_does_not_cross_sessions`); leak safety is three-layered (short TTL + observed-delete + fresh-turn clear, `test_stale_flag_is_cleared_at_turn_start`); `LLMRouter`'s public contract is untouched (cancel check lives entirely in `ChatService`'s loop).
- **Terminal-event discipline holds:** every path ends in exactly one `done` / `cancelled` / `error`. The broad `except Exception` (BLE001) does not swallow `asyncio.CancelledError` (BaseException in 3.11), so client disconnect still cancels the generator, and the new `_run_iteration` `finally` releases the upstream stream promptly on early cancel.
- **No SSE frame injection:** `_format_sse` JSON-encodes the payload (`json.dumps`) and `CancelledEvent` carries only a server-minted `message_id` — no raw untrusted content on the wire.
- **Persistence coherence:** partial-answer persistence on mid-stream cancel appends a content-only assistant message (no orphan `role="tool"` created, since partial tool-call deltas are dropped without executing), and iteration-boundary cancel persists already-completed tool round-trips — both keep the next turn's history valid. The `role="tool"` orphan-on-count-cap concern is P1-05's documented/deferred `RedisSessionMemory` trim, not introduced here.
- **Security:** cancel endpoint has no auth/ownership — anyone who knows a `session_id` can cancel it. Correctly documented as a known P3 AuthZ gap per the task constraint; `session` Path param is length-bounded (1–200, matching `ChatRequest`) and used only as a fixed-prefixed Redis key (keys are binary-safe, no injection). Acceptable at P1.
- **Concurrency note for P1-08:** the fresh-turn clear at `stream_turn` start means cancel should not be relied on to stop a *different, concurrent* turn on the same `session_id` (a new turn wipes the flag). Two concurrent turns per session is not a supported P1 scenario, but the frontend should target cancel at the current in-flight turn only.
- **v1 cleanup confirmed:** no residual `active_requests` module dict — fully replaced by the Redis-backed registry (grep clean; remaining references are docstrings explaining the replacement).
