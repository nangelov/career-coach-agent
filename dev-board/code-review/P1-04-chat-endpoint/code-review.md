| C1 | minor | app/schemas/chat.py:48 | `ChatRequest.history` is `list[ChatMessage]` with no role restriction, and `ChatService.stream_turn` prepends it verbatim to the messages sent to the LLM. A client can inject `role="system"` instructions or fabricate `role="tool"` results into its own turn, steering the model / pre-empting guardrails (P10). Impact is confined to the caller's own session (no shared state), so not gating — but the escape hatch widens the untrusted-input surface. | Restrict the interim history escape hatch to `user`/`assistant` roles (drop/reject `system` and `tool`), or remove `history` and rely solely on the `SessionMemory` seam. At minimum, note the trust assumption so P10 guardrails cover it. |
| C2 | minor | app/api/chat.py:71-75 | `get_chat_service` lazy-builds and caches on `app.state` with no lock. Two concurrent first requests can each run `build_chat_service()` (two `LLMRouter`s + two `redis.asyncio` clients); only the last one written to `app.state` is closed on shutdown, leaking the other's Redis client. | Acceptable for P1 (interim, P2 moves to shared pools), but build the service in the lifespan startup (or guard with an `asyncio.Lock`) to avoid the double-build/leak. Flag for P2. |
| C3 | minor | app/services/chat.py:155,177 | `history` + server-side memory can diverge: when a caller passes `history` and a `session_id`, only this turn's `produced` messages are appended to `SessionMemory`, so a later turn omitting `history` replays only the last turn and loses the earlier context. Partially documented in `engineer.md`, but the divergence isn't guarded. | Document the "history XOR server memory" expectation in the `ChatRequest.history` field/docstring (or seed memory from supplied history on first use) so P1-05/P1-08 don't build on the ambiguity. |
| N1 | nit | app/services/chat.py:174-178 | Plain-answer path persists `ChatMessage(role="assistant", content=result.content)` and emits `done` even when the model returned neither content nor tool calls (`content is None`). Yields a `done` with zero `token` events and stores an empty assistant turn. | Optionally treat "no content and no tool calls" as a terminal `error`/retry rather than a successful empty turn. |
| N2 | nit | app/services/chat.py:202 vs 207-217 | Inconsistent persistence on non-success exits: the iteration-cap path persists `turn.produced`, but the `except` paths (LLM/unexpected errors) drop the whole turn (user message not persisted). Both are defensible, but the asymmetry is undocumented. | Add a one-line comment stating the intent (failed turns are intentionally not persisted; capped turns are) so future maintainers don't "fix" one to match the other. |

## Notes
- Correctness of the core loop is solid: token-by-token streaming (deltas yielded the instant they arrive), streamed `tool_calls` reassembled by `index` via `_ToolCallAccumulator`, iteration cap enforced, and every terminal path yields exactly one `done` **or** one `error` — no unhandled mid-stream 500. `except Exception` (BLE001) does not swallow `asyncio.CancelledError` (BaseException in 3.11), so client-disconnect cancellation still propagates correctly.
- Security posture is sound for the walking skeleton: no `run_python_code`/arbitrary execution; tool results flow back as untrusted JSON strings only; SSE frames are built via `json.dumps`, so newlines/`event:`/`data:` in token or tool content are escaped — no SSE frame-injection from model or tool output. `session_id` is a bounded (`max_length=200`) opaque dict key. The only untrusted-input note is C1.
- Layering respected: `api/chat.py` is thin (validate + `_format_sse` + `StreamingResponse`); the whole model⇄tools loop lives in `services/chat.py`; the router stays HTTP/SSE-free. `SessionMemory` ABC is a clean, narrow seam for the P1-05 Redis swap. No ReAct/text-parsing anywhere (native tool-calling only) — honors the locked v2 decision.
- Verification reproduced locally in `.venv`: `ruff check` clean, `mypy app/` clean (29 files), `pytest -q` → **41 passed**. Service tests exercise all four required paths (plain answer + streaming + memory replay, tool round trip, iteration cap, all-models-failed); API smoke test asserts SSE framing + 422 on empty message. All acceptance criteria met.
- All five findings are `minor`/`nit` and interim-scoped; none block P1's walking skeleton. C1 is the one worth carrying forward into P10 guardrails; C2 into P2 pool wiring.
