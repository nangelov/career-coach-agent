## Notes
- **Security of the guest→account binding (acceptance #3) — sound.** The upgrade ticket is minted server-side from the *verified* guest `session_id` (`current_user.session_id` off the validated JWT in `begin_upgrade`), never a client-supplied id. `POST /api/auth/upgrade` is guarded by `require_auth` and 409s a non-guest. The ticket is an opaque `uuid4().hex` carrying only the guest session id (no secret), single-use (`pop`), short-lived (`UPGRADE_TICKET_TTL_SECONDS`, default 300s). Crucially `begin_login` **consumes** the ticket *before* the cross-origin redirect to the provider, so a Referer leak to the IdP carries a dead ticket. Same-origin URL/log/history exposure remains but grants nothing (already-consumed, names-only). Acceptable and documented.
- **History carryover (acceptance #1/#2) — correct.** Keeping the same `session_id` leaves the Redis working memory untouched, so the live conversation continues. `_pair_turns` correctly reduces the transcript to clean user↔assistant turns (drops tool-call scaffolding = assistant content=None, drops tool results, preserves an orphan user turn with `None`). Backfill reuses `ConversationStore.persist_turn` (the exact logged-in path); `conversation_id=None` per turn get-or-creates a single conversation per session (confirmed idempotent), so a multi-turn transcript lands in one conversation, not one-per-turn.
- **Best-effort posture — correct.** `_backfill` catches `Exception` (not BaseException, so CancelledError propagates), logs and stops on first failure without aborting the upgrade; the record is still promoted so future turns persist. `upgrade()` returns False (→ fresh session) when the guest session lapsed or is already a user (replay-safe); combined with single-use `state`/ticket this makes double-callback and replay no-ops.
- **No cross-contamination (acceptance #4) — verified.** Each ticket binds one guest session id; each OAuth-state record carries one `upgrade_session_id`; the concurrent-upgrade test (`test_concurrent_upgrades_do_not_cross_contaminate`) proves distinct sessions/users/history. Good.
- **Layering / interfaces — clean.** New `UpgradeTicketStore` port (services/) before the Redis adapter (repositories/), reusing the existing `StoreRedis` seam; `GuestUpgradeService` is a separate collaborator injected optionally into `SsoAuthService` (existing SSO tests unaffected). Router stays thin.
- **Verification reproduced:** the 15 P3-03 tests pass; `ruff check` clean; `mypy` clean on the two new service modules. Engineer's pre-existing-mypy-noise claim is consistent with prior P3 reports.
