- OCR is CPU-bound work correctly pushed off the event loop via `asyncio.to_thread`; engine build is guarded by double-checked locking. All engine/binary exceptions are normalized to `DocumentParseError`, and `UnsupportedDocumentError` (a `DocumentParseError` subclass) is caught by the composite so an unsupported-format fallback (e.g. OCR on DOCX) degrades gracefully rather than propagating — good.
- Composite exposes the single `DocumentParser` interface (P5-03/P5-04 callers stay engine-agnostic); the ordered `fallbacks` chain plus `ReservedVlmOcrParser` (raises `NotImplementedError`, never wired into a live chain) is a clean, typed extension point for the §5.1 VLM tier — reserved, not implemented, per task. Best-effort selection (keep the richest extract when no tier is fully usable) and `_annotate` metadata (`ocr_fallback_used`/`text_layer_usable`/`text_layer_reason`/`text_char_count`, JSON-serializable via `model_copy`) are sound.
- Tests cover all three acceptance cases (fallback triggers on no/low text, does NOT trigger on a normal document, OCR output conforms to `ParsedDocument`) plus graceful-degrade and best-effort paths. The DRY extraction to `formats.py` is reasonable and behavior-preserving for `DoclingParser`.
- Security: OCR processes untrusted uploaded bytes only through the OCR toolchain (Tesseract/OCRmyPDF/Ghostscript) — inherent attack surface of those binaries, out of scope here; no shell, no injection, no `run_python_code`-style execution, no secrets. Temp files use `TemporaryDirectory` (auto-cleaned). No concern to gate on.
